# مدل قیمت‌گذاری دو جنسیتی (بانوان / آقایان)

قیمت‌گذاری در «تهران لیزر» به‌صورت **دو ردهٔ جنسیتی** مدل شده و منبع آن فقط پایگاه‌داده است.

---

## ۱. مدل داده

### جدول `service_prices` (از `migrations/0001_init.sql`)
```sql
CREATE TABLE service_prices (
  id               TEXT PRIMARY KEY,
  service_id       TEXT NOT NULL REFERENCES services (id) ON DELETE CASCADE,
  pricing_category TEXT NOT NULL CHECK (pricing_category IN ('male', 'female')),
  amount           INTEGER NOT NULL CHECK (amount >= 0),
  currency         TEXT NOT NULL DEFAULT 'IRT',
  created_at       TEXT NOT NULL,
  updated_at       TEXT NOT NULL,
  UNIQUE (service_id, pricing_category)   -- یک قیمت برای هر خدمت × هر رده
);
```

- **قانون درست‌بودن (DB-level):** `pricing_category IN ('male','female')` — هیچ ردهٔ سومی پذیرفته نمی‌شود.
- **یگانگی:** `UNIQUE (service_id, pricing_category)` مانع ثبت قیمت تکراری برای یک خدمت در یک رده است.
- در TypeScript، این رده‌ها در `src/domain/booking/booking.types.ts` تعریف شده‌اند:
  ```ts
  export const PRICING_CATEGORIES = ['male', 'female'] as const;
  export type PricingCategory = (typeof PRICING_CATEGORIES)[number];
  ```

## ۲. واحد پول — «هزار تومان» 🔑

> **مقدار `amount` بر حسب هزار تومان ذخیره می‌شود، نه تومان.**

- `amount = 330` یعنی **۳۳۰٬۰۰۰ تومان** (در رابط کاربری به‌صورت «۳۳۰٬۰۰۰ تومان» نمایش داده می‌شود).
- هنگام نمایش: `amount * 1000` سپس `toLocaleString('fa-IR')`.
- واحد نمایشی از تنظیمات می‌آید: `currency_label` (پیش‌فرض «تومان»)، و کد ارز `IRT`.
- **بدون تغییر واحد نیست:** اگر عددی بدون ضرب در ۱۰۰۰ وارد شود، تعرفه به‌شدت اشتباه ثبت می‌شود.

## ۴. ویرایش تعرفه از داشبورد (بدون کد)

مسیر: **`/admin/services`** (پنل مدیریت → خدمات و تعرفه‌ها).

- جدول دسکتاپ دو ستون جدا دارد: **«تعرفه مصوب بانوان»** و **«تعرفه مصوب آقایان»** — با نمایش «استعلام تلفنی» وقتی قیمتی ثبت نشده.
- دکمهٔ **افزودن خدمت جدید** و **ویرایش خدمت** یک مودال با فیلدهای زیر باز می‌کند:
  - نام خدمت، Slug، مدت جلسه (دقیقه)، ترتیب نمایش، وضعیت انتشار (فعال/غیرفعال)، توضیح کوتاه
  - **کارت تعرفه دوگانه:** «تعرفه مصوب بانوان» و «تعرفه مصوب آقایان» — با راهنمای صریح **«واحد: هزار تومان»** و پیش‌نمایش زندهٔ معادل تومان.
- دکمهٔ **ویرایش سریع تعرفه** کنار هر قیمت، مستقیماً همان رده را ویرایش می‌کند.
- در موبایل (≤۷۶۸px) کارت‌های جدول‌جای، هر دو تعرفه را زیر هم نشان می‌دهند.
- ذخیره در پایگاه‌داده **D1** انجام می‌شود (نه فایل ثابت) — تعرفه‌ها بلافاصله در سایت عمومی بازتاب می‌یابند.
- صفحهٔ عمومی خدمات، کاتالوگ دیتابیس را روی مقادیر پیش‌فرض overlay می‌کند (`src/pages/services/index.astro`).

### الزام کاربر
> «قیمت هم خودت بزن فعلا ولی قابل تغییر باشه از داشبورد اصلی» — یعنی ویرایش تعرفه باید **همیشه از داشبورد** در دسترس بماند؛ مقداردهی اولیه نباید ویرایش‌پذیری را حذف کند.

## ۵. محاسبهٔ سمت سرور (سرور مقتدر)

محاسبهٔ نهایی در `src/domain/pricing/pricing.ts` → `calculateQuote()`:

- ورودی: خدمت، آرایهٔ قیمت‌ها، ردهٔ انتخابی، درصد تخفیف.
- اگر خدمت غیرفعال باشد → خطای `SERVICE_INACTIVE`.
- اگر برای ردهٔ درخواستی قیمتی ثبت نشده باشد → خطای `PRICE_NOT_CONFIGURED` (همان «استعلام تلفنی»).
- درصد تخفیف به بازهٔ ۰–۱۰۰ محدود می‌شود؛ `totalAmount = baseAmount - discountAmount`.
- **هیچ قیمت یا مدت ارسالی از کلاینت مورد اعتماد نیست** — مبلغ ذخیره‌شدهٔ هر رزرو فقط از همین تابع می‌آید.
- تابع `hasPriceFor()` تعیین می‌کند آیا یک رده قیمت دارد یا باید «استعلام» نمایش داده شود.
