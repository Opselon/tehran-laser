# سیستم افزونه‌ها (Feature Modules / Plugin Hub)

هر سکشن، نوار یا قابلیت سایت یک **ماژول** است: در `/admin/plugins` روشن/خاموش
می‌شود، ترتیبش عوض می‌شود، تنظیمات اختصاصی‌اش ویرایش می‌شود و با یک کلیک به
پیش‌فرض کارخانه بازمی‌گردد — دقیقاً مثل افزونه‌های وردپرس حرفه‌ای.

> قانون طلایی: **ماژول غیرفعال = هیچ چیز.** نه مارکاپ، نه placeholder، نه
> اشاره‌ای در API. سکشن‌ها سمت سرور گیت می‌شوند (`isOn('key')`) و از
> `GET /api/v1/features` فقط ماژول‌های **فعال و عمومی** بیرون می‌آیند.

---

## ۱. منبع حقیقت کد است، دیتابیس فقط override

| لایه                 | فایل                              | مسئولیت                                                                                                     |
| :------------------- | :-------------------------------- | :---------------------------------------------------------------------------------------------------------- |
| رجیستری (منبع حقیقت) | `src/domain/features/registry.ts` | تعریف هر ماژول: کلید، نام، آیکن، دسته، `defaultEnabled`، `defaultOrder`، فیلدهای تنظیمات + قواعد اعتبارسنجی |
| حالت (State)         | `src/domain/features/state.ts`    | merge کردن override روی default، gateها (`isOn`) و resolve config — خالص و Node-testable                    |
| Persist              | `src/server/features.ts`          | تنها خواننده/نویسندهٔ جدول `feature_modules`                                                                |
| API                  | `src/server/http/router.ts`       | مسیرهای عمومی و ادمین                                                                                       |
| هاب ادمین            | `src/pages/admin/plugins.astro`   | رابط SSR مدیریت                                                                                             |
| قرارداد              | `docs/API.md`                     | مسیرها و کدهای خطا                                                                                          |

- **هیچ seed داده‌ای در migration نوشته نمی‌شود.** افزودن ماژول = فقط یک entry
  در `FEATURE_MODULES`. «default IS the absence»: نبود ردیف دقیقاً یعنی همان
  default رجیستری.
- `DELETE /admin/features/:key` = «حذف override و بازگشت به پیش‌فرض»، نه حذف
  ماژول. ماژول‌های `internal` (مثل `sms-campaigns`) هرگز در API عمومی نمی‌آیند.

---

## ۲. مدیریت از پنل

۱. به `/admin/plugins` بروید (منوی «فرماندهی → افزونه‌ها و بخش‌های سایت»).
۲. کلید روشن/خاموش هر افزونه را بزنید — تغییر بلافاصله در سایت اعمال می‌شود
(مسیرهای عمومی از edge cache پاک می‌شوند).
۳. «تنظیمات» هر افزونه متن‌ها، لینک‌ها و عددهای اختصاصی آن را ویرایش می‌کند؛
«بازنشانی» مقدارها را به پیش‌فرض کارخانه برمی‌گرداند.
۴. با فلش‌های بالا/پایین، ترتیب نمایش سکشن‌ها را بدهید.
۵. افزونه‌های **پرمیوم** (حالت طلایی) را می‌توانید به مشتری به‌عنوان قابلیت
پرداختی ارائه دهید — خاموش مانده تا فعال شود.

> افزونه‌ها در داشبورد ادمین (`/admin`) هم خلاصه‌شده‌اند: وضعیت روشن/خاموش هر
> ماژول در یک نگاه، با لینک مستقیم به هاب.

## ۴. جایی که ماژول‌ها را می‌خوانیم

- `/` — همهٔ `sections`: `src/pages/index.astro`
- نوارها و دکمه‌های سراسری — `src/layouts/PublicLayout.astro`
- `/booking` و `/blog` (مسیرها) — `src/pages/booking.astro`، `src/pages/blog/index.astro`، `src/pages/blog/[slug].astro`
- API عمومی — `GET /api/v1/features`
- هاب ادمین — `/admin/plugins`
- داشبورد ادمین — `/admin` (خلاصهٔ وضعیت)

شکستن هرکدام توسط تست `tests/unit/module-gating.test.ts` در CI گرفته می‌شود:
سکشنی که `isOn()` ندارد، تست قرمز است.

## ۵. قواعد ایمنی

- کلید ناشناخته در `PUT` → **404** (هرگز ردیف جدید ساخته نمی‌شود).
- کلید ناشناخته در `config` → **422** (هرگز خاموش نادیده گرفته نمی‌شود).
- config قبل از UPSERT با zod اعتبارسنجی می‌شود؛ دیتابیس نمی‌تواند حالت
  نامعتبر نگه دارد.
- خطای خواندن D1 در صفحهٔ عمومی → fallback به default رجیستری، نه صفحهٔ خالی.
- ماژول `internal` هرگز از API عمومی بیرون نمی‌رود.
- نوشتن هر ماژول: audit log + پاک کردن edge cache.
